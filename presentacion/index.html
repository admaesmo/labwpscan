Pregunta guia

Como puede un auditor observar un sitio WordPress desde fuera y convertir esa informacion en acciones defensivas?

Lo que ve el escaner

  • Versiones detectables
  • Plugins y temas
  • Usuarios expuestos
  • Archivos sensibles

Lo que decide el analista

  • Riesgo real
  • Prioridad
  • Mitigacion
  • Evidencia para el informe

Contexto

WordPress es muy usado porque permite construir sitios rapidamente con plugins y temas. Esa flexibilidad tambien aumenta la superficie de ataque.

Nucleo Plugins Temas Usuarios API REST XML-RPC Backups Logs

Que es WPScan

WPScan es un escaner de seguridad de caja negra especializado en WordPress.
  • Analiza el sitio desde fuera, mediante peticiones HTTP.
  • Busca pistas de WordPress, plugins, temas y usuarios.
  • Relaciona componentes detectados con vulnerabilidades conocidas.
  • Se usa en auditorias autorizadas y revisiones defensivas.

Uso etico

WPScan debe usarse solo en sistemas propios, laboratorios o activos con autorizacion explicita.
  • Definir alcance antes del escaneo.
  • No ejecutar fuerza bruta sin permiso especifico.
  • Evitar pruebas agresivas en produccion.
  • Proteger tokens, salidas y reportes.

Teoria base

Reconocimiento

Recopilar informacion visible del objetivo.

Fingerprinting

Inferir tecnologias y versiones por sus pistas externas.

Enumeracion

Listar usuarios, plugins, temas o archivos detectables.

Gestion de vulnerabilidades

Identificar, priorizar, corregir y verificar riesgos.

Dos escenarios

Escenario 1

WordPress actualizado

http://localhost:8080

Escenario 2

WordPress vulnerable

http://localhost:8081

  • WordPress 5.8
  • Contact Form 7 5.3.1
  • WooCommerce 3.4.5
  • Twenty Nineteen 1.5

La carpeta deja listo el entorno, los comandos y la plantilla para documentar evidencias.

Levantar escenarios

Escenario actualizado:

cd laboratorio-wpscan
docker compose up -d

Escenario vulnerable:

chmod +x scripts/preparar-wordpress-vulnerable.sh
./scripts/preparar-wordpress-vulnerable.sh

El actualizado queda en `8080`; el vulnerable queda en `8081`.

Comandos de practica

wpscan --url http://localhost:8080
wpscan --url http://localhost:8080 --enumerate u
wpscan --url http://localhost:8080 --enumerate ap,at
wpscan --url http://localhost:8081 --enumerate u,ap,at
wpscan --url http://localhost:8081 --enumerate vp,vt --api-token TU_TOKEN

La comparacion permite ver hallazgos normales frente a componentes desactualizados.

API token

Para consultar vulnerabilidades conocidas se usa un token de WPScan.

wpscan --url http://localhost:8080 --api-token TU_TOKEN
El token no debe compartirse, mostrarse en capturas ni subirse a repositorios.

Que debe arrojar

Actualizado

  • WordPress detectado
  • Tema activo
  • Usuarios si son enumerables
  • Pocas alertas criticas

Vulnerable

  • Componentes antiguos
  • Plugins detectables
  • Vulnerabilidades con API token
  • Mayor prioridad de correccion

Prueba controlada

wpscan --url http://localhost:8080 \
  --usernames admin \
  --passwords wordlists/passwords-lab.txt

Sirve para demostrar el riesgo de credenciales debiles en un entorno propio.

En sistemas reales requiere autorizacion explicita y limites claros.

Elemento Ejemplo

Defensa en profundidad

Monitoreo
Actualizaciones
MFA
WordPress
  • Actualizar nucleo, plugins y temas.
  • Eliminar componentes no usados.
  • Proteger backups, logs y configuraciones.
  • Revisar periodicamente con herramientas autorizadas.

Limitaciones

  • Puede generar falsos positivos o falsos negativos.
  • No reemplaza revision manual ni revision de codigo.
  • No analiza toda la logica de negocio.
  • Depende de lo visible desde el exterior.
  • Para vulnerabilidades conocidas requiere API token.

Cierre

WPScan ayuda a entender como se ve un WordPress desde fuera.

En el laboratorio se conectan tres ideas: reconocimiento, gestion de vulnerabilidades y mitigacion defensiva.

Escanear no es el final: el valor esta en interpretar y corregir.
